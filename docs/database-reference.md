## Views and database automation

No application views or materialized views, custom triggers or stored routines were found in public. No RLS policies or partition children were found. All public tables have RLS disabled. PostgreSQL internal FK triggers/system views are separate. Only plpgsql is installed as an extension. Reports are generated by TypeScript/Prisma services.

## Design and implementation

- Normalized relational tables use CUID string IDs, generated by Prisma for most entities, plus composite keys in junction tables.
- ClientAssignment connects users and clients and stores per-agent/per-client hourly rate. DealContact and InteractionContact/Company/Deal represent many-to-many links.
- Primary keys, unique indexes, foreign keys and CHECK constraints enforce selected integrity rules. Composite indexes serve organization/client/date/status query patterns. All inspected indexes are B-tree.
- JSONB stores metadata/context snapshots/provider fields; Document.fileData is bytea, so uploaded document bytes are stored in PostgreSQL.
- Money generally uses integer cents; commission rates are floating-point percentages. Time logs retain trackedSeconds and minutes.
- Prisma transactions keep local operations atomic. RepeatableRead provides consistent report snapshots; transactions do not roll back remote CRM/calendar operations.
- SELECT FOR UPDATE locks serialize time-tracking cursors, deal commission changes and ledger corrections. Transaction-scoped advisory locks serialize OTP requests by email and duplicate Twilio events by provider ID.
- Unique keys plus upsert support import/sync duplicate prevention. Token consumption and sequence checks guard selected replay cases. They do not guarantee globally exactly-once external delivery.
- AuditLog records actions. CommissionLedgerEntry records payments/adjustments. SyncRun, DealHandoff, Appointment and AgentClickUpRecord persist provider status/error information. This is not a full event-sourcing architecture or database-enforced immutable history.
- Password hashes use salted scrypt; session, invitation and OTP values use hashes. Provider credentials use AES-256-GCM application encryption with key configuration outside PostgreSQL.
- Tenant/client/agent access is enforced by authenticated server services and scoped queries, not PostgreSQL RLS. Foreign keys establish parent existence but do not by themselves enforce matching organizationId/clientAccountId across rows.
- Provider IDs (ClickUp task IDs, HubSpot/Zoho IDs) are external references, not cross-provider database foreign keys. Some local identifier-like fields are also not FKs; inspect the constraint catalogue below.
- Prisma migrations track schema history. Additional historical tables are preserved. No schema/data changes were made by this inspection. Backup/restore automation was not audited.
